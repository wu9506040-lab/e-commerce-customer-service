> **电商全渠道智能客服系统**：独立设计开发的多渠道 AI 客服平台（Vue3 + FastAPI + MySQL/Redis/Qdrant + 通义千问）。自研闲鱼 WebSocket 协议栈与 mtop 签名（摆脱第三方 CLI 依赖），实现 Cookie 四层自愈（HTTP 续期 + Playwright 免密登录）、ackDiff 消息补拉、本地意图路由 + 分 Agent 话术管线 + 回复数据校验，端到端回复延迟从 54s 优化至 10s 内；RAG 数据中台支持多格式文档解析（PDF 页眉剔除/表格/脚注）、语义分块、增量向量化与多渠道知识库隔离。Python 后端 5.2 万行，97 个测试文件，311 次提交，7×24 无人值守运行。

## 3. 已完成功能清单（按模块）

### 3.1 闲鱼渠道守护进程（daemon）
- **自实现 WebSocket 收发**：LWP 协议注册/心跳/ACK，彻底替代第三方 goofish-cli
- **ackDiff 消息补拉**：轻量通知（仅消息指针）主动拉取完整内容 + 60s 周期兜底（参考开源项目没有的能力）
- **多消息合并**：4s debounce 窗口（标点快发 1.5s），买家连发多条合并为一次回复
- **消息去重**：message_id 组合键去重 + 已见剔除（服务端重推不重复回复）
- **噪声过滤**：系统卡片 `[去支付]`、MsgTips 营销消息静默
- **智能分诊**：纯问候与实质问题分流；no_reply 意图（"你是谁/什么模型"）静默不回复

### 3.2 回复生成管线（多 Agent）
- **本地意图路由**：price/tech/default 关键词路由（零 LLM 开销，合批双意图叠加）
- **场景识别**：售前/售中/售后三场景 YAML 话术库（few-shot 示例 + 人设）
- **议价系统**：议价轮次 SQLite 计数（1h 过期）+ 赠品梯度话术 + 动态注入
- **上下文**：会话历史（Redis + MySQL 写穿）+ 买家画像（mtop 数据源）+ 商品信息本地缓存
- **人工接管**：卖家发切换关键词 → 会话接管 1h（超时自动恢复）

### 3.3 回复质量与安全管线
- **MessageGuard**：承诺性敏感词拦截（"已退款/已转账"）→ 安全替代话术
- **ReplyValidator 数据校验**（纯正则零开销）：markdown/引用角标/占位符剥离、裸 None 字面量、长度保险丝（>200 字句界截断）、价格幻觉检测（三层模式 vs 商品价格白名单，观察模式）
- **站外引流过滤**：微信/QQ/支付宝等词 → 整条替换平台内沟通提醒
- **空回复兜底**：LLM 返空发拟人话术，绝不静默丢买家消息

### 3.4 体验优化
- **打字模拟**：延迟 = 基础 + 字数×系数（上限 3s），>48 字句界拆两条分发送
- **拟人话术**：40 字口语短句约束、few-shot 示例对齐
- **发送可靠性**：无限重试（限流独立配额 + 指数退避）

### 3.5 Cookie 生命周期（四层自愈）
- L1 mtop Set-Cookie 自愈重签；L2 HTTP passport 续期（180s）
- L3 Playwright 免密登录（自动点「快速进入」→ 强鉴权页 → 抓全量 cookie，必需字段校验防假成功）
- L4 人工兜底（仅浏览器免密记忆失效时）

### 3.6 RAG 数据中台
- **多格式解析**：PDF（页眉页脚跨页剔除、字号层级章节、表格转 markdown、脚注独立块、图片导出）、Markdown 标题栈、TXT、JSON
- **语义切分**：句子边界切分绝不截断句中 + 章节内贪心打包 + 尾句重叠
- **增量入库**：source+content_hash 去重、批量向量化、幂等可重跑、MySQL 镜像
- **渠道隔离**：payload.channel 标签（xianyu/mall）+ 检索过滤，多渠道知识库互不干扰

### 3.7 运维与可靠性
- **看门狗**：30s PID 探活 + 自动拉起（Windows OpenProcess 安全探活）
- **Docker Compose**：五容器编排，源码 bind-mount 开发模式
- **健康检查**：XianyuHealth 聚合 watcher/cookie/debounce/配额状态
- **会话数据隔离**：闲鱼/商城 session 前缀 + MySQL 视图层切分

## 4. 关键技术难点与解决方案

### 4.1 闲鱼 WebSocket 协议逆向与自实现
- **难点**：闲鱼 IM 走私有 LWP 协议（注册帧 /reg、心跳、syncPushPackage 推送），消息体 base64+MessagePack 双层编码，无公开文档
- **解决**：对照两个开源参考项目逐字段逆向；实现 token 签名、注册帧、心跳、ACK 全协议栈；遇到服务端只推"消息指针"（仅 messageId 无内容）的情况，自研 **ackDiff 主动补拉机制**——比参考项目多一层保障，解决轻量通知丢消息问题
- **踩坑**：ACK 帧格式抄错（多包了一层 lwp 字段）导致服务端不认、消息延迟 3 分钟——用日志里的真实帧解码定位根因

### 4.2 Cookie 生命周期管理（10 分钟 token 有效期）
- **难点**：_m_h5_tk 仅 10 分钟有效且只在浏览器活跃访问时续期；纯 HTTP 静默调用会滑向"半失效 session"（表现为 FAIL_SYS_TOKEN_ILLEGAL）
- **解决**：设计四层自愈体系（见 3.5）；L3 用 Playwright 操作**系统 Chrome**（规避 headless 指纹风控）+ 独立 tmp profile（规避 Chrome 单例锁）自动完成免密登录
- **踩坑**：Windows 下 `os.kill(pid, 0)` 是 TerminateProcess 不是探活——watchdog 第一版直接把 daemon 杀了，改用 ctypes OpenProcess + GetExitCodeProcess

### 4.3 意图识别 + 多 Agent 编排
- **难点**：LLM 意图分类慢且有成本；单一通用 prompt 长回答、跑题、议价无策略
- **解决**：**三级路由**——本地关键词/正则优先命中（零 LLM 开销）→ 规则 miss 才 LLM 分类；按意图挂独立短 prompt（price/tech/default，40 字硬约束）；议价轮次计数 + 赠品梯度策略动态注入；合批消息双意图叠加
- **效果**：回复长度减半、LLM 流式时间同步下降、话术按场景精准

### 4.4 RAG 检索优化与数据中台
- **难点**：通用 RAG 管线（改写→多路→检索→精排）在 IM 场景太重（实测前置 LLM+检索吃掉 20s+）；商城与闲鱼知识库互相污染
- **解决**：**渠道感知路由**——常规问题走快速通道（跳过 RAG，system_prompt 直出 LLM），异常降级才走 RAG 且按渠道过滤；知识库 payload 打 channel 标签 + Qdrant filter 检索隔离
- **数据管线**：多格式解析（PDF 页眉页脚剔除/表格/脚注）→ 句子边界语义分块（绝不截断句中）→ 增量向量化（hash 去重幂等）

### 4.5 回复数据校验（幻觉防线）
- **难点**：LLM 会编造价格（实测输出"新机 1500+"与 ¥99999 定价自相矛盾）、残留占位符/markdown
- **解决**：纯正则校验管道（零延迟）——占位符替换、格式剥离、长度保险丝、价格幻觉三层模式检测（¥金额/数字+元/价格语境词）对比商品价格白名单；观察模式先攒数据再收紧

### 4.6 端到端延迟优化（54s → 10s 内）
- 分阶段日志拆解定位瓶颈：意图误判→消息合并策略→ACK 格式→RAG 前置管线→模型出字，每一层单独优化：
  debounce 30s→4s、随机延迟 0-3s→0-1s、跳过 RAG 前置、打字模拟参数收紧、分批发送

## 5. 项目亮点与差异化（对比开源方案）

对比对象：XianyuAutoAgent、xianyu-auto-reply（GitHub 主流闲鱼客服开源项目）

| 维度 | 开源参考项目 | 本项目 |
|------|-------------|--------|
| 消息收发 | 依赖第三方 goofish-cli subprocess | **全自研协议栈**（LWP + msgpack + mtop 签名），零外部依赖 |
| 消息可靠性 | 轻量通知静默跳过（有丢消息隐患） | **ackDiff 主动补拉** + 周期兜底 + 组合键去重 |
| Cookie 续期 | 单一方案（手动换 / 浏览器抓取） | **四层自愈**（含 Playwright 免密登录 + 假成功防御），7×24 无人值守 |
| RAG | 无或仅简单向量检索 | **数据中台**：多格式解析（PDF 复杂版式）+ 语义分块 + 增量入库 + 多渠道隔离 |
| 回复质量 | 单一 prompt | **分 Agent 短 prompt + 议价轮次系统 + 数据校验管道**（价格幻觉检测为参考项目所无） |
| 可观测性 | 基础日志 | 分阶段延迟拆解、健康检查聚合、外部看门狗、97 个测试文件 |
| 部署 | 脚本启动 | Docker Compose + watchdog + 任务计划，**24h 无人值守** |

**核心差异化叙事**：不只是"接了个开源项目改改"——协议栈自研、兜底体系自设计（四层 Cookie 自愈、ackDiff 补拉、数据校验管道都是参考项目没有的增强），并有完整的量化优化过程（54s→10s 的分阶段拆解）。
